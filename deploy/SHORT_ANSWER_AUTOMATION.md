# 简答题 AI 建议分与人工确认

更新：2026-10-21。当前业务规则以本文件为准，替代早期“AI明确结果自动采用”的描述。

## 阅卷流程

1. 进入“成绩与判卷”，选择考试，点击“AI一键判卷”。
2. 空答自动记最终0分，不调用AI，不需要人工确认。
3. 有答案的作答自动生成并展示AI建议分和逐点依据，最终分保持未确认。建议0分、部分分和满分都需要人工确认。
4. 阅卷人员认可时点击“确认此分”；不认可时输入人工最终分并“修改并确认”。原AI建议保留，便于比较。
5. 全部题目评分就绪后，通过原入口统一公布。AI生成建议和人工确认都不自动公布。

采用宽松的按要点给分：独立正确要点分别给分，同义、概括、等价表述均认可，不要求逐字背出参考答案；不臆测没有写出的内容。首次使用仍由阅卷人员判断AI是否符合实际尺度。

## 行为

- 仅 SHORT_ANSWER 使用新流程。发布事务保存本场快照和准备任务，事务内不调用 AI。
- 统一语义宽松规则。评分点是有原文依据的原子叶子点；模型给 FULL / NONE / REVIEW，Java 根据固定权重一次 HALF_UP 取整。
- 考试快照锁定规则 ID、满分和计分配置；题库新版本不改已锁定标准。普通卷和个人错题卷都支持。
- 一个考试一个活动判卷任务。仅纳入点击时已提交、尚无最终分且尚无有效AI建议的非空作答；后续提交需再次点击。不会自动关闭考试。
- 专用两个工作线程，调度每轮最多领取两项。任务、重试、租约、规则和缓存都持久化。浏览器关闭不影响执行。
- 180 秒租约到期可重新领取，旧领取令牌无法提交。外部请求在进程崩溃后可能重发；最终写分、审计受令牌、作答内容、修订号、快照和人工分检查保护。
- 技术错误最多自动尝试三次；额度/输入限制直接报错。无法确定或规则异常转人工。空答自动0分，其他失败不计0分。
- 有答案的明确结果只保存AI建议分及逐点依据，不写最终分；包括建议0分和满分在内，均须人工确认或改分。空答自动0分无需确认。总成绩仍须调用原共用公布入口。
- 缓存使用完全相同的原始作答，避免证据映射不确定性；不同满分只复用逐点结论，重新换算分数。缓存不保存密钥。人工改为不同分数后失效该条判定，不追溯改其他人的最终分。
- 新策略最终分 / 快照满分 ≤30% 为错题，等号包含。旧 null 策略记录沿用历史相似度规则，不回填；日常练习、错题掌握和复习排序保持原逻辑。

## 配置与上线顺序

`HNEXAM_SHORT_AUTOMATION_ENABLED` 默认 `false`。停用时任务仍可保存，页面会明确提示后台未启用，可继续人工评分。

1. 安排发布窗口，停止旧应用对数据库的写入；备份正式数据库并做恢复验证。不要使用清库、初始化或覆盖整库脚本。
2. 构建新代码。迁移工具是独立 Java 主类，不启动 Spring，也不会加载 `.env.local`：

   ```powershell
   mvn -f backend/pom.xml -DskipTests compile
   # 在安全的进程环境中设置 JDBC_URL / JDBC_USER / JDBC_PASSWORD。
   # 不将密码写进命令历史、交接文件或提交到 Git。
   java -cp "backend/target/classes;<对应MySQL或H2的JDBC驱动jar绝对路径>" com.huaneng.shanyin.hnexam.tools.ShortAnswerMigration
   ```

3. 工具会验证四张基础表的必要字段，获取数据库互斥锁，逐项加列、建表和建索引，在 `hnexam_schema_change` 记录 `20261020_short_atomic_v2` 的步骤及 COMPLETE。重复执行会检查已有结构并补齐剩余步骤；MySQL DDL 非整体事务，失败后修复原因再运行，不删表回滚。
4. 用新二进制、`SPRING_JPA_HIBERNATE_DDL_AUTO=validate` 启动，初期保持后台开关关闭。确认人工阅卷、旧 JSON 展示和共用公布可用后，再设置 `HNEXAM_SHORT_AUTOMATION_ENABLED=true` 并重启新版本。
5. 检查 AI 配置、现有全局/用户额度和超时设置。发布准备计入发布人，逐点判定计入作答用户；沿用原 AI 调用账本，不绕过限流。
6. 用经过人工标注的代表性简答样本验证真实模型语义质量，再扩大使用范围。本次模拟测试验证流程和计分，不等于证明真实模型准确率。

上述步骤适用于其他尚未升级的环境；本机本轮执行状态见顶部“本机启用”。

## 增量结构

- `short_answer_rubric`：可空复用键（唯一）、格式/业务/规范化版本、准备令牌/租约、校验时间与错误。原规则不覆盖。
- `exam_question`、`personal_exam_question`：规则 ID、计分配置、锁定时间；普通卷额外标记无可靠原始快照的历史兼容行，禁止用当前题库自动判历史简答。
- `exam_attempt_answer`：可空策略版本、判定缓存 ID。旧行默认 null。
- `short_answer_job`、`short_answer_job_item`：任务、目标、状态、重试、租约和版本。
- `short_answer_decision_cache`：校验后的逐点判定、有效模型配置指纹、缓存状态。

不创建第二套评分标准表，不改变原成绩公布接口，不回填历史评分策略。

## 运维与回退

- 进度：`GET /api/exams/{id}/short-review/jobs`。
- 创建：`POST /api/exams/{id}/short-review/jobs`。
- 重试失败项：`POST /api/exams/{id}/short-review/jobs/{jobId}/retry`。
- 同场活动任务重复点击返回原任务。规则需人工修订时，到题库高级评分标准保存并确认新版本，再重新启动待判任务；不会重新绑定已锁定的考试版本。
- 停止自动化：关闭开关，停止/重启新版本工作器；保留任务、规则、审计和已确定分数，继续人工处理。重开后过期租约恢复。
- 不直接换回不理解 AUTO_READY / 新版 JSON 的旧 jar；不删列删表，不用旧整库覆盖上线后的合法操作。
- 若历史快照在本次上线以前已被旧系统用当前题库回填，源码无法事后证明其真实来源。需要业务核对；本改造只对可识别的缺失/回填情况阻止自动判定。
