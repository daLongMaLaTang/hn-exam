# AI 调用控制（第二阶段）

## 行为

三条判题路径（日常填空练习、考试填空自动复核、管理员主观题建议）共用数据库用量账本。每次向模型发送的请求计一次，多空题可能计多次；可接受答案直接匹配、空白答案等不调用 AI 的情况不扣额度。个人额度归属于练习用户或答卷学员，标识由服务端读取，不接受客户端指定，也不会发送给模型。

调用前通过固定账本行的短事务锁，原子检查全局／个人并发和日额度，扣次数并登记租约；然后释放数据库连接，再发 HTTP 请求。成功、失败、超时、中断均尝试释放租约。已获准调用的次数不返还，避免失败重试无限消耗费用。数据库准入失败时不发送请求。

超过额度、并发繁忙或响应不可信时，日常练习记录 `assessed=false`，不当成答错；考试填空沿用人工复核流程；管理员建议接口返回 429 和可读原因。没有新增自动重试。超限并不会停止客观题本地判分、提交答卷或人工评分。

## 默认值与调整

配置位于 `backend/src/main/resources/application.yml`，通过环境变量覆盖，生效需要重新加载应用。

| 环境变量 | 默认值 | 含义 |
| --- | ---: | --- |
| HNEXAM_AI_MAX_CONCURRENT | 8 | 同库实例合计活跃租约数 |
| HNEXAM_AI_USER_MAX_CONCURRENT | 1 | 每学员活跃租约数 |
| HNEXAM_AI_DAILY_CALLS | 20000 | 全局每日请求次数 |
| HNEXAM_AI_USER_DAILY_CALLS | 200 | 每学员每日请求次数 |
| HNEXAM_AI_MAX_INPUT_CHARS | 16000 | 题干、参考答案、作答的字符总量上限 |
| HNEXAM_AI_MAX_OUTPUT_TOKENS | 1024 | 发送给服务商的 max_tokens |
| HNEXAM_AI_TIMEOUT_SECONDS | 60 | 请求超时上限，实际取已有设置和此值中较小者 |

所有限额必须为正数；输出上限不超过 8192，超时上限不超过 120 秒。每日按 Asia/Shanghai 零点切换，已进行中的调用完成后仍记到准入当天。多实例必须使用一致配置、共用同一数据库并保持时钟同步。重启应用不会清空日额度。

全局额度由练习和判卷共享；练习耗尽额度时，判卷仍可人工完成。默认值是可调整的保护值，不代表已完成 2000 人真实 AI 容量规划。

## 运维可观测性

新增 `GET /api/ai/usage`，仅用户名 `admin` 且具有 `SYSTEM_ADMIN` 权限的账号可读。沿用原有登录凭据访问。返回当日准入、成功、失败、超时、租约失联、限额拒绝、当前活跃数、剩余次数、累计耗时，以及服务商报告的输入／输出 token 数和当前限制；不包含密钥、题目、作答或个人名单。前端设置仍只需 API key，本阶段没有新增前端页面。

`missingUsage` 表示未得到完整 token 用量的已结束／失联调用，不能把这部分成本理解为零。模型返回格式不合格，但附带有效 usage 时，仍累计该用量。`rejected` 统计数据库准入拒绝，不包含输入长度检查的拒绝。

次数、输入长度、输出 token 上限共同约束调用规模；本阶段没有按实时单价换算人民币，也没有实现服务商账户余额或金额预算硬上限。最终收费以服务商账单为准。

## 持久化与恢复

新增 `ai_usage_bucket` 和 `ai_call_lease` 两张表，沿用项目 Hibernate schema update 机制；没有修改现有学员密码、题库或答卷结构。用量日桶保留 90 天（另保留永久互斥行），定时清理每小时运行。

租约在请求超时时间加 30 秒后可回收；准入、用量查询和定时清理都会回收过期租约。进程异常退出或完成记账失败不会退回已扣次数；过期后标为 abandoned 和 missingUsage。重复完成不会二次记账，也不会释放其他请求的租约。完成记账失败只输出固定日志，不输出请求、API key 或异常正文。

并发控制针对应用登记的有效租约。客户端超时／进程终止无法证明服务商立即停止计算，长时间进程暂停或时钟偏差也可能造成租约到期后旧请求仍在运行；不能把租约数宣称为服务商侧绝对并发或精确账单。

## 验证方式

`AiUsageServiceTest` 默认使用隔离 H2，覆盖跨服务实例竞争、全局日额度竞争、个人并发／日额度、重启、跨日完成、租约回收、幂等完成、输入与超时上限、清理。传入 `-Dhnexam.ai-usage.mysql=true -Dtest=AiUsageServiceTest` 时，只能连接硬编码的隔离 MySQL 库 `hn_exam_loadtest_20261011`，密码从 `HNEXAM_LOADTEST_PASSWORD` 读取。该模式使用 create-drop，禁止改成业务库。

协议测试使用模拟 HTTP，检查限额拒绝时不发送请求、输出上限、超时／中断／错误响应的记账和释放；集成测试检查真实准入后 HTTP 回调没有事务或绑定数据源连接，以及用量接口权限和超限练习的未评定状态。测试不会调用真实模型。
