# 华能山阴培训考试系统 · 上线操作清单

> 适用版本：`hn-exam 0.1.0-SNAPSHOT`（Spring Boot 3.5.16 / Java 17 / Vue 3.5 / Vite 8）
> 部署形态：单台云服务器，Docker 编排 MySQL 8 + Redis 7 + 后端 + Caddy，**前端与后端同域名**。

---

## 0. 为什么不用 WorkBuddy 托管服务跑后端

| 项目 | 你的系统 | 托管沙箱 |
|---|---|---|
| 运行时 | Java 17 + Maven | 仅 Node / Python / Go / 静态 |
| 数据库 | MySQL 8（线上 profile 强制） | 只给一个 HTTP 端口，无伴生库 |
| 缓存 | Redis 7（JWT 状态、登录防刷） | 无 |

结论：后端必须自建服务器。前端 `dist` 可以放托管服务，但代码里 5 处 `/api` 是相对路径
（`src/api.ts` 两处、`QuestionsView.vue` 两处、`ProfileImport.vue` 一处），拆到独立域名
必须改成 `VITE_API_BASE` + 配 CORS + 第二张证书。本方案把前端也放在同一域名下，
**零代码改动**、无跨域、一张证书，考试系统更稳。

## 1. 买服务器

### 配置

| 项 | 建议 |
|---|---|
| CPU/内存 | **2核4G 起步**，长期用建议 4核8G |
| 系统盘 | 60G 以上（题库、日志、MySQL 数据、备份） |
| 带宽 | 3~5M 固定带宽够用；API 请求小，考生做题不传大文件 |
| 系统 | Ubuntu 22.04 LTS 或 Debian 12 |
| 地域 | 大陆（广州/上海/北京）延迟低，但**域名必须备案**；急上线选**香港**，免备案 |

> 内存怎么分：MySQL 缓冲池 256M + JVM 堆 1G + Redis/Caddy/系统约 500M ≈ 1.8G，
> 4G 机器有余量。2G 机器跑不动 MySQL + JVM，别省这 100 块。

### 价格参考（2026年10月查，下单前以活动页为准）

| 平台 | 配置 | 首年 | 备注 |
|---|---|---|---|
| 腾讯云轻量 | 2核4G 5M / 60G | 约 188 元 | 续费同价，个人首选 |
| 腾讯云轻量 | 4核8G 5M / 60G | 约 450 元 | 后续扩量 |
| 阿里云轻量 | 2核4G 200M峰值 / 50G | 约 199 元 | 不限流量 |
| 华为云耀 | 2核4G 3M | 约 118 元 | 新用户专享 |

### 备案（大陆节点必看）

- 域名解析到大陆服务器，**必须先完成 ICP 备案**，否则 80/443 会被拦截。
- 阿里云/腾讯云控制台都有免费备案入口，个人备案通常 7~23 个工作日。
- 不想等 → 买**香港节点**，买完直接用，代价是大陆访问延迟 30~60ms。考试系统可接受。

## 1.5 200 人在线的配置依据

按 200 人同时在线测算，瓶颈是内存：

| 组成 | 占用 |
|---|---|
| JVM（堆 1.5G + 元空间/线程） | ~2.0G |
| MySQL 8（缓冲池 512M + 开销） | ~0.8G |
| Redis | ~0.15G |
| 系统 / Docker / Caddy | ~0.4G |
| **合计** | **约 3.4G** |

- **2核4G**：能跑，但没有余量，考试峰值容易 OOM。只适合 100 人以内。
- **4核8G**：推荐。留出 4G 冗余，管理员导报表、题库导入不卡顿。
- CPU 不是瓶颈：答题时主要是自动保存和切屏上报，峰值约 20~40 QPS，2 核够用。

**免费试用对照（2026年10月）**

| 平台 | 免费配置 | 时长 |
|---|---|---|
| 腾讯云 | 个人 2核2G 3M | 1 个月，实名即可，不绑卡 |
| 腾讯云 | 个人 2核4G 蜂驰 CVM | 7 天 |
| 腾讯云 | 企业 4核8G 12M | 1 个月，每日限量 |
| 阿里云 | 个人 2核2G + 300 元额度 | 1 个月，限全新账号 |
| 华为云 | 2核1G 1M | 1 个月，太弱 |
| Oracle Always Free | 4核 ARM + 24G / 200G / 10TB | 永久，但需绑卡、抢容量、有封号风险 |

**建议路径**：先领腾讯云 2核4G 免费机验证部署流程，再买 4核8G 正式机。
免费机不要做压测，只验证「能跑起来」。

验证用 `docker-compose.verify.yml`：无 Caddy、无证书，8080 直接暴露，用 IP 访问，
**不需要域名也不需要备案**。

```bash
# 服务器上（已装 Docker）
cd /opt/hnexam/prod
cp .env.example .env && vi .env      # 填数据库/Redis 密码和 JWT 密钥
docker compose -f docker-compose.verify.yml up -d --build
docker compose -f docker-compose.verify.yml logs -f app
# 浏览器访问 http://服务器IP:8080

# 验证通过后切正式编排
docker compose -f docker-compose.verify.yml down
docker compose up -d --build
```

> 验证阶段 `app` 绑的是 `0.0.0.0:8080`，公网可直接访问，仅限短期使用。
> 正式编排里这一行已被改回 `127.0.0.1:8080`。

## 2. 服务器初始化

```bash
# 用 root 或 sudo 用户登录
ssh root@你的公网IP

# 1) 装 Docker（官方脚本，国内如拉取失败可换阿里云镜像源）
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 2) 时区校正（日志时间要对得上）
timedatectl set-timezone Asia/Shanghai

# 3) 放行端口（云控制台安全组里也要放行 22 / 80 / 443）
#    Ubuntu 自带 ufw 时：
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
```

> 安全组/防火墙**只需放行 22、80、443**。MySQL 3306、Redis 6379、后端 8080
> 在 compose 里已经只绑 `127.0.0.1`，公网摸不到。

### 加一块 swap（2核4G 强烈建议）

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 3. 本机构建产物

在**你自己的 Windows 机器**上执行（不要在服务器上编译）：

```bash
cd /e/hnexam
bash deploy/prod/build.sh
```

脚本做三件事：`mvn package` → 复制 jar 为 `deploy/prod/app.jar` → `npm run build` 并复制
`dist` 到 `deploy/prod/www/`。

> 如果你的 Maven 仓库在 D 盘，带上参数：
> `MAVEN_ARGS="-Dmaven.repo.local=D:\web\maven-repo" bash deploy/prod/build.sh`

生成结果：

```
deploy/prod/
├── app.jar        ← 约 94MB，后端可执行包
├── www/           ← 前端静态文件
├── Dockerfile
├── docker-compose.yml
├── Caddyfile
├── ops.sh         ← 服务器上的运维脚本（状态/自检/备份/更新）
└── .env.example
```

## 5. 配置 .env

```bash
cd /opt/hnexam/prod
cp .env.example .env

# 生成三个强随机串
openssl rand -base64 24   # → MYSQL_PASSWORD
openssl rand -base64 24   # → MYSQL_ROOT_PASSWORD
openssl rand -base64 24   # → REDIS_PASSWORD
openssl rand -base64 48   # → HNEXAM_JWT_SECRET
```

编辑 `.env`（vi/nano 都行），重点四项：

| 变量 | 说明 |
|---|---|
| `SITE_DOMAIN` | 只写域名，如 `exam.example.com`，**不要带 https://** |
| `ACME_EMAIL` | 证书到期提醒邮箱 |
| `PUBLIC_ORIGIN` | 与 SITE_DOMAIN 对应，如 `https://exam.example.com` |
| `HNEXAM_JWT_SECRET` | 上线后**永远不要改**，改了所有人掉线 |

`HNEXAM_BOOTSTRAP_PASSWORD` 是首次创建 `admin` 用的密码，登录后系统强制要求改。

## 7. 数据怎么办

系统 `ddl-auto: update`，**空库首次启动会自动建表**，不需要手工执行 SQL。数据有两种来法：

### 方式 A：全新开始（推荐，干净）

1. 管理员登录 → 人员与权限 → 用 Excel 导入 114 名考生；
2. 题库管理 → 批量导入题库，用系统 Excel 模板填写课程/章节；
3. 组卷 → 发布考试。

> 注意：线上 `.env` 里 `HNEXAM_QUESTION_BANK_PATH` 已置空，启动时不会去读那份
> `E:/xwechat_files/.../安规考试题库.docx`（那个路径在服务器上不存在）。题库改由页面导入。
> 想一次性导入原 Word 题库：把 docx 上传到服务器，临时把该变量指向容器内路径即可。

### 方式 B：迁移现有数据

本机已有 MySQL 备份（`.local/backups/*.sql`）。导出并导入：

```bash
# 本机：从本地 MySQL 导出（库名按你实际的改）
mysqldump -u root -p --single-transaction --default-character-set=utf8mb4 hn_exam > hnexam_prod.sql

# 上传
scp hnexam_prod.sql root@公网IP:/opt/hnexam/prod/hnexam_prod.sql
```

服务器上导入（**先启动数据库，再导，最后起应用**）：

```bash
cd /opt/hnexam/prod
docker compose up -d mysql redis
sleep 30
docker compose exec -T mysql mysql -uroot -p"$(grep MYSQL_ROOT_PASSWORD .env | cut -d= -f2)" hn_exam < hnexam_prod.sql
docker compose up -d --build
```

> 迁移后**立即改掉所有账号密码**，尤其是 admin 和 114 个初始工号密码。
> 备份里如果带着本机 `.env.local` 的 JWT 密钥，线上仍要用新生成的。

## 8. 域名与 HTTPS

1. 域名服务商处加 A 记录：`exam` → 服务器公网 IP，等生效（`ping exam.example.com` 验证）。
2. Caddy 首次启动会自动申请证书，通常 30 秒内完成：

```bash
docker compose logs caddy | tail -20
# 看到 "certificate obtained successfully" 即成功
```

3. 浏览器打开 `https://exam.example.com`，应直接进入登录页。

排错：

| 现象 | 原因 |
|---|---|
| 证书申请失败 | 域名没解析到本机 / 80 端口被墙 / 大陆节点未备案 |
| 打开是 404 | `www/` 目录为空，本机 build.sh 没跑或没上传 |
| 刷新子路由 404 | Caddyfile 的 `try_files ... /index.html` 被改坏了 |
| 502 Bad Gateway | app 容器没起来，`docker compose logs app` 看报错 |

## 10. 日常运维

常用操作已封装成 `ops.sh`，在服务器 `cd /opt/hnexam/prod` 后：

```bash
bash ops.sh status      # 容器状态、磁盘、内存
bash ops.sh health      # 后端 / MySQL / Redis / HTTPS 四项自检
bash ops.sh logs        # 跟踪后端日志
bash ops.sh backup      # 备份数据库，自动保留最近 14 份
bash ops.sh update      # 重新构建并重启后端
bash ops.sh restore backup/hnexam-20261019-010000.sql.gz
```

原始命令（需要单独操作时）：

```bash
cd /opt/hnexam/prod

# 查看状态
docker compose ps

# 看后端日志（最近 200 行）
docker compose logs --tail=200 app

# 重启后端（改配置后）
docker compose restart app

# 发新版本：本机重新 build.sh → 上传 →
docker compose up -d --build app
```

### 定时备份（考试周建议每天一次）

```bash
# 加到 root 的 crontab：crontab -e
0 2 * * * cd /opt/hnexam/prod && bash ops.sh backup >> data/logs/backup.log 2>&1
```


### 备份（每周至少一次，考试前必做）

```bash
cd /opt/hnexam/prod
mkdir -p backup
docker compose exec -T mysql mysqldump -uroot -p"$(grep MYSQL_ROOT_PASSWORD .env | cut -d= -f2)" \
  --single-transaction --default-character-set=utf8mb4 hn_exam \
  | gzip > backup/hnexam-$(date +%F).sql.gz
```

下载回本地保存：`scp root@公网IP:/opt/hnexam/prod/backup/*.sql.gz .`

### 磁盘

```bash
df -h        # 系统盘用到 80% 就要清理
docker system prune -af   # 清理旧镜像（会删掉未使用的镜像层，谨慎）
```

日志已挂载到 `data/logs`，不会随容器重建丢失。要限制体积可加 logrotate，或定期清空：

```bash
truncate -s 0 data/logs/*.log
```

## 11. 与本地开发的差异

| 项 | 本地 | 线上 |
|---|---|---|
| 数据库 | H2 文件 `data/hnexam.mv.db` | MySQL 8 容器 |
| Redis | `init-local-infrastructure.ps1` 起 | 同一个 compose 里 |

| 题库 Word | 首次启动自动导入 | 关闭，改为页面导入 |
| 启动方式 | `start-local.ps1` / IDEA | `docker compose up -d` |

## 12. 常见故障对照

| 症状 | 排查方向 |
|---|---|
| 启动即退出，日志报 `require-configured` | `HNEXAM_JWT_SECRET` 为空。mysql profile 强制要求 |
| 启动报 JDBC 连接失败 | MySQL 还没 healthy；或 `.env` 密码与库不一致。`docker compose logs mysql` |
| 登录 500 / Redis 报 NOAUTH | `HNEXAM_REDIS_PASSWORD` 与 `REDIS_PASSWORD` 不一致 |
| 登录 403「当前访问地址未获允许」 | 前端提示语对应后端 `app.web.allowed-origins`，检查 `PUBLIC_ORIGIN` 是否与浏览器地址栏完全一致（协议、域名、端口） |
| 页面白屏 | `www/` 没内容，或 `index.html` 引用的 `/assets/*` 未上传 |
| 上传题库报 413 | Caddy `request_body` 上限与后端 `max-request-size` 都要放宽 |
| 内存告警 / 容器被 OOM Kill | `JAVA_OPTS` 的 `-Xmx` 调小，或升配置、加 swap |
| 时间差 8 小时 | 三个容器都要 `TZ=Asia/Shanghai`，MySQL 还要 `--default-time-zone=+08:00` |
