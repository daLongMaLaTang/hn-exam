# 优化第一阶段：事务与登录保护

## 已修改

- 连接池默认使用 READ COMMITTED。答卷仍通过父记录悲观锁串行保护同一份答卷，保留锁后刷新及重复交卷校验。这样减少不同答卷首次插入答案时，MySQL 默认 REPEATABLE READ 间隙锁造成的相互阻塞；没有移除唯一约束，也没有降低写入持久性。
- 刷题提交拆成“读取题目快照 → 无事务调用 AI → 短事务重新校验并保存”。保存前加当前用户锁，与考试开始使用同一把锁；重新检查账号、题目状态、题干/参考答案和进行中的考试。AI 等待期间开始考试后，禁止返回该考试答案；题目变化时要求重新作答。
- 登录失败限制同时按账号+IP（8 次）、账号（20 次）、IP（200 次）计数，默认窗口 900 秒。成功登录不清空 IP 累计失败数。本机限流记录每分钟清理过期项，最多 20000 条。配置项分别为 app.login.max-failures、max-account-failures、max-ip-failures、failure-window-seconds、max-local-entries；学校/企业共用出口时需依据实际失败率调整。
- 不再使用公开 JWT 默认密钥。MySQL 配置要求提供 HNEXAM_JWT_SECRET，缺失或不足 32 字节时拒绝启动；显式填写旧公开密钥也拒绝启动。本地非 MySQL 模式未配置密钥时使用每次启动随机生成的临时密钥，重启后重新登录。已有独立密钥继续有效，不能把随机生成的密钥写入代码仓库。

## 验证与限制

新增回归检查覆盖 AI 调用无事务/无当前线程数据库连接、AI 等待期间开考后的答案保护、题目修改后的旧判题结果拒绝、公开密钥伪造令牌失败、跨账号和跨 IP 登录攻击限制及限流内存边界。

MySQL 压测仍使用专用的 hn_exam_loadtest_20261011 和专用账号，绝不对业务库使用 create-drop。最终压测数据、测试数量和剩余工作以任务输出目录中的 2026-10-13 交接记录为准。

这不是全部优化完成：统一初始密码、AI 调用总量/并发限制、月度分析查询、题库分页、学习心跳、依赖告警与突发连接失败仍需继续处理。新的锁和隔离策略也需在真实部署拓扑下复测；2000 份在考答卷不等于 2000 个请求同时成功。

锁行为参考：[MySQL 8.0 官方事务隔离文档](https://dev.mysql.com/doc/refman/8.0/en/innodb-transaction-isolation-levels.html)。READ COMMITTED 仍会为外键和重复键检查使用部分间隙锁，因此不能声称它消除了所有死锁。
